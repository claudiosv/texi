# Roadmap

- [ ] Replace `project.main = "main.tex"` with `targets`, a list of PDFs to build, e.g. `targets = ["main.tex", "appendix.tex"]`.
- [ ] Replace the `updmap` and `fmtutil` binaries. In the `archive` install method texi writes `updmap.cfg`, `fmtutil.cnf` and the language files itself (`texi.tlactions`), but it still invokes the `updmap` and `fmtutil` binaries to generate the maps and format files. A texi implementation would merge `updmap.cfg` files and write `pdftex.map`, `psfonts.map` and the dvipdfmx maps into `.texenv/texmf-var` directly.
- [ ] Build formats without the `fmtutil` binary: read `fmtutil.cnf` and run the engines with the right `-ini` arguments into `.texenv/texmf-var`, so a texi project does not depend on the system `fmtutil` scripts.
- [ ] Match tlmgr's line length when `archive` writes `.tlpobj` files. The tlpdb index does not keep the original `longdesc` line breaks, so texi re-wraps at 70 characters, and the result differs from the `.tlpobj` tlmgr writes. Check what width tlmgr uses and use it as the default, or store the original line breaks in the index.
- [x] Kept configuration pseudo-records out of dependency edges. The tlpdb uses the same `depend` field for real package dependencies (`depend latex`) and for settings and release info in the `00texlive.*` entries (`depend opt_location:__MASTER__`, `depend release/2026`). The parser now stores the latter in `TlPackage.settings` and a separate `setting` table of the index, `TlPackage.depends` holds package names only, and `texi tlpdb info` shows a `Settings` section. The `archive` planner uses the new `texi.resolver`, which builds edges from real dependencies only.
- [ ] Resolve across multiple repositories (package identity and repository selection before traversal). `texi.resolver` works against exactly one package index.
